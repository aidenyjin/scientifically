# Scientifically

A Duolingo-style app for learning **science**, built for **laptops**. Bite-sized lessons with 16 kinds of
interactive questions, hearts, XP, streaks, daily quests, leagues, achievements, a shop, spaced-repetition
practice and a cast of six characters.

The app is a **shell**: it contains no course content of its own. Courses are generated by an AI model from a
server-side API key, validated against a strict schema, reviewed in the admin area, and then published.

---

## Quick start

Requires Node 20+.

```bash
npm install
npm run setup      # creates .env, the SQLite database and the demo course
npm run dev        # http://localhost:3000
```

- Click **Get started** to learn as a guest (create a profile later to keep progress), or log in as the
  seeded demo user: `demo@scientifically.dev` / `scientist`.
- Admin: <http://localhost:3000/admin> — password is `ADMIN_PASSWORD` in `.env` (`change-me` by default).
- Use another port with `npm run dev -- -p 3001`.

## Generating courses with AI

1. Put your key in `.env` (server-side only, never sent to the browser):
   ```
   AI_PROVIDER="anthropic"
   ANTHROPIC_API_KEY="sk-ant-..."
   AI_MODEL=""            # optional; blank uses the adapter default
   ```
2. Either use the admin UI (**/admin → Generate**) or the CLI:
   ```bash
   npm run generate -- --subject chemistry --topic "acids and bases" --level "High school" \
     --units 3 --lessons 4 --exercises 10 --save
   ```
   `--out pack.json` writes a file instead of saving; `npm run generate -- --validate pack.json` checks a file
   without calling the API.
3. Review the draft in **/admin → Packs**: every exercise is rendered with its real component, problems from
   automatic checks are flagged, and you can edit JSON, delete exercises, regenerate a lesson or play it.
4. **Publish**. Learners pick courses from the course switcher (top right) or during onboarding.

Set `AI_PROVIDER="mock"` to try the whole pipeline without a key (it assembles packs from built-in examples).
`AI_PROVIDER="openai"` with `OPENAI_API_KEY` is also supported.

### How generation works

Two stages: an **outline** (units → lessons → objectives and skill tags), then **one call per lesson**. Each
lesson is validated with Zod and every exercise runs its own `autoCheck` (e.g. equations must balance, numeric
answers are recomputed, simulation targets must be reachable). Failures are sent back to the model with the
exact errors, up to two retries; anything still wrong is flagged for review. Prompts are built from code: the
JSON Schema, each question type's examples and writing notes, the character cast and the simulation models.

## Letting AI agents create courses

The opposite direction also works: give an outside AI agent (Claude, ChatGPT, Cursor, Codex, your own script) a key
for this app and it can write courses straight into Scientifically.

1. Open **/admin → Agents** and create a key. Untick "Let this agent publish" to keep everything it writes as a
   draft for you to review.
2. The key is shown once, with three ready-to-copy options:
   - **A message to paste into any agent that can make web requests** (Claude Code, Codex, Cursor, ChatGPT agent
     mode…). It points the agent at the guide and the API.
   - **A connector URL** (`/api/agent/mcp?key=…`) for chat apps that support custom MCP connectors (Claude, ChatGPT…).
   - **A `claude mcp add` command** for Claude Code.
3. Ask the agent for a course. It reads the guide (`GET /api/agent`): the same content contract, quality rules and
   per-type examples the built-in generator uses. It then creates the course as a draft, adds a unit at a time,
   fixes the problems the automatic checks report and publishes it.

Agents get the same checks as imports: schema errors are rejected, and a course can't be published (or a live
course changed) while any exercise fails its `autoCheck`. Agents can read every course but only change the ones
made through the agent API. Revoking a key locks its agent out immediately. Cloud apps (Claude.ai, ChatGPT) can't
reach `localhost`, so deploy the app first for those, or set `APP_URL` if the app runs behind a proxy.

| Endpoint (`Authorization: Bearer <key>`) | What it does |
|---|---|
| `GET /api/agent` | The guide (Markdown) |
| `GET /api/agent/schema` | JSON Schema of a pack |
| `POST /api/agent/validate` | Check a pack without saving |
| `GET /api/agent/packs` · `GET /api/agent/packs/{id}` | List courses · read one |
| `POST /api/agent/packs` | Create a course (`{"pack", "status"?}`) |
| `PUT /api/agent/packs/{id}/units/{unitId}` | Add or replace a unit (`{"unit", "position"?}`) |
| `PATCH /api/agent/packs/{id}` | Replace a course and/or set its status |
| `POST /api/agent/mcp` | The same operations as MCP tools (key in the header or `?key=`) |

## Environment variables

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | SQLite file, default `file:./dev.db` |
| `AI_PROVIDER` | `anthropic` (default), `openai` or `mock` |
| `AI_MODEL` | Model id; blank for the adapter default |
| `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` | Provider keys (server only) |
| `ADMIN_PASSWORD` | Admin login. If unset, admin is open in development (with a banner) and disabled in production |
| `AUTH_SECRET` | Signs session cookies; **required (16+ chars) in production** |
| `APP_URL` | Optional public URL (e.g. `https://sci.example.com`) used in links given to AI agents; default: the request's host |

Optional AI tuning: `AI_EFFORT`, `AI_FALLBACKS=off`, `AI_OUTPUT_MODE`, `ANTHROPIC_BASE_URL`, `OPENAI_BASE_URL`
(see `.env.example`).

## Deploying

The app needs a **long-running Node server** (generation jobs run in the background, and SQLite needs a
persistent disk). Good fits: Fly.io, Railway, Render or any VPS with a volume for the database file.

```bash
npm ci && npm run build
DATABASE_URL="file:/data/scientifically.db" npx prisma db push
DATABASE_URL="file:/data/scientifically.db" npm start
```

Set `AUTH_SECRET`, `ADMIN_PASSWORD` and your AI key in the host's environment.

**Postgres instead of SQLite:** change `provider = "sqlite"` to `"postgresql"` in `prisma/schema.prisma`,
`npm install @prisma/adapter-pg pg`, swap `PrismaBetterSqlite3` for `PrismaPg` in `src/server/db.ts` and
`prisma/seed.ts`, and set `DATABASE_URL` to your Postgres URL.

## Project layout

```
src/
  app/            routes: (app) shell pages, (auth) welcome/onboarding/login, lesson/[lessonId], admin, dev
  content/        the content contract: Zod schemas, exercise registry, demo pack, solve()
  exercises/      one folder per question type (schema, grade, core, Component, tests)
  engine/         lesson state machine (pure) + Zustand store
  game/           XP, hearts, streaks, goals, quests, achievements, leagues, SRS, shop (pure, tested)
  characters/     the cast, expressions, reactions, cosmetics
  sims/           simulation models (pure) and their animated visuals
  sound/          Web Audio sound effects
  server/         db, auth, repos, services (wire game rules to the DB), ai pipeline, agent API, admin gate
  components/     UI kit, lesson player, path, shell, shop/quests/leagues/profile/admin pieces
docs/PLAN.md      the build plan and the decisions log
```

## Adding a new question type

1. Create `src/exercises/<type>/` by copying `multiple_choice/`:
   - `schema.ts` — Zod schema extending `exerciseBaseSchema` with `type: z.literal("<type>")`, plus a response schema.
   - `grade.ts` — pure `grade(exercise, response)` and optional `autoCheck(exercise)`; `grade.test.ts`.
   - `index.ts` — the `ExerciseCore`: label, schemas, grade, autoCheck, `promptNotes` for the AI, and 2–3 `examples`.
   - `Component.tsx` — the UI (`ExerciseProps`): keyboard support, locked + right/wrong states after checking.
2. Register it in `src/content/registry.ts` (import, `exerciseCores`, `exerciseSchema`) and
   `src/content/registry.client.ts` (component map).
3. Add a case to `src/content/solve.ts`.
4. Run `npm test` — the registry tests check your examples validate, pass autoCheck and are answerable — then
   look at `/dev/<type>`. The demo pack and AI prompts pick the type up automatically.

## Tests

- **Unit/integration (Vitest):** schemas, every exercise grader, the lesson engine, all game rules (including
  time-zone and day-boundary cases), the AI pipeline with a mock provider, the agent API and its MCP server, and
  lesson completion against a temporary SQLite database.
- **End-to-end (Playwright):** guest onboarding → lesson → results → streak; the entire demo course; keyboard-only
  play; out of hearts; admin generate → review → publish; agent key → API-made course → publish → revoke.
